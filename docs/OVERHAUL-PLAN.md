## Information architecture

1. **Hero:** keep the contour sphere, pointer response and scale. One action enters Frontier. Real snapshot dates and counts only; no fake live counters.
2. **Frontier:** the main full-width visual defaults to 8–12 verified current flagships spanning major labs. Domain, benchmark and view controls share one cohort. Raw values, coverage and first-use score definitions stay visible. Direct labels and source detail on selection. Overall scores appear only when eligible and comparable.
3. **Capability and cost:** scatter/Pareto view for explicit task tokens. Input, cached input, output and reasoning billing are shown. Unknown prices stay unknown. No implied success-rate costs without measurements. Cost and speed remain separate from capability.
4. **US–China head-to-head:** two selected models, aligned domain dumbbells, benchmark drilldown and common-test coverage. Source lab headquarters. Keep global/multinational/unknown labs in the catalogue. Never infer geography from model language or hosting. No country winner from unmatched tests.
5. **Open weights:** parameter-group explorer and small multiples. Representatives first, full filtered results on demand. Total-parameter bands: under 10B, 10–35B, 35–100B, 100–300B, 300B+, undisclosed. Show activated parameters separately for MoE. Weights availability and open-source licence are distinct. Meta is required even when parameters/results are undisclosed.
6. **All models:** searchable, sortable, paginated/virtualized directory with lab, family, release, openness, modality, parameters, tested configuration, coverage, pricing and source filters. Include the union of all supported sources and unscored entries. Do not claim literally every model ever created.
7. **Methods and benchmark library:** domain map, current versions, inclusion/exclusion reasons, weights, missingness, evidence type, freshness and changelog. Put long explanations here and in detail panels.

Navigation: Frontier, Head-to-head, Open weights, Models, Methods. Share URLs preserve models, cohort, metric, source tier and view. Filters, exports and accessible tables must agree with chart marks. Main plots never automatically render hundreds of series.

Unknown conditions stay explicit and affect comparability. Retrieval time cannot be presented as evaluation time.

Pricing records provider, currency, effective/retrieved date, tiers, caching, reasoning billing, source URL and limitations. API cost is not self-hosted inference cost.

Refresh is a documented runnable command and CI workflow with bounded retries, schema checks, last-success status and a reviewed branch/PR before publication. No paid evaluation campaign. New aliases, schema drift, suspicious jumps, stale observations, duplicate families and unresolved conflicts must be reported. Provide coverage/changelog and public CSV/JSON exports.

## Scoring

Raw benchmark and domain views are primary. Publish a versioned method, not a universal-intelligence claim. Eleven capability domains are the taxonomy; safety, preference, latency and pricing are independent adjacent measures. Specialist/audio/video observations extend profiles without silently changing every model's denominator.

Normalize using defined metric bounds/direction, not the current winning model. Document chance corrections/floors/ceilings. Keep incompatible variants apart. Start with equal domain weights; cap related benchmark families so duplicated math/coding results cannot dominate. Investigate redundancy on matched data where available and state limits elsewhere.

An overall comparison uses one declared common benchmark/configuration panel for its cohort and fixed domain weights. Display panel, domain coverage and scoring version. Never renormalize separately per model for missing observations, impute zeros, or give an overall score to an ineligible model. Return insufficient coverage and useful domain/raw views instead. A text-only panel is labelled text-only. Head-to-head uses compatible common observations and reports exclusions. Saved links retain the scoring definition.

Allow explicit user domain weights, reset and shareable settings, labelled separately from the default index. Produce defensible weight sensitivity, leave-one-suite-out and independent-source-only checks. Report rank instability and ties. Statistical intervals require valid source intervals or item-level samples; heuristic/weight ranges are not CIs. Meaningful tests include hand-calculated fixtures for nulls, low-is-better, saturation, missing domains, duplicate/correlated suites, conflicts, aliases and incompatible harnesses.
