# Source acceptance before ranking

The ingestion stage captures public records. Capture alone does not establish that a record belongs in a scored comparison. Scoring must audit the final ingestion output and repair its source contracts before using them.

- A file under a model repository's `refs/pr/*` belongs to a proposed change. Its target owner is not proof of its submitter or the model publisher's endorsement. Preserve the submission author, PR status, resolved revision, verified flag and exact source. Confirm values against a publisher-controlled release/model card or an authoritative benchmark result before admitting them to the default scored panel. Unconfirmed submissions can be inspected separately, clearly labelled.
- A number between 0 and 100 does not establish percentage units. A number below one does not establish a fraction. Source metric definitions and the result column's unit must support any conversion. Preserve raw values; inferred or unknown units cannot silently become documented units or enter the default aggregate.
- Each observation gets its own exact suite, family, task, split, metric direction and evaluated configuration. A numeric match alone does not join different tasks or tool conditions. Shared test families, including related tau benchmark versions, must receive a joint family cap.
- A provider's `hugging_face_id` can point to a related checkpoint rather than an identical API model. Confirm variant identity before transferring checkpoint measurements or openness to that API version. Preserve related-model references separately from exact aliases.
- Retrieval bounds must be stated and validated. Follow paginated model-source results to the admitted source's end or report the actual bounded scope. Selecting only two leaderboard rows per suite is a discovery sample, not complete result ingestion. Expand actual supported result rows and primary publisher sources rather than presenting the sample as all results.
- The launch observation floor is at least 15 real benchmark suites across 8 capability domains. Professional, safety, preference and audio/video remain separate panels and cannot fill the capability-domain floor. The breadth of the catalogue and registry does not count as measured coverage.

The main page must provide a useful current frontier cohort spanning major labs, including Meta, with genuine supported observations and useful raw/domain views where an overall panel is ineligible. Do not fill charts with invented scores, present old preview data as a current release, or call an empty default ranking complete. Check the current primary release sources and preserve source dates separately from listing dates.

Add meaningful failure fixtures for unverified PR claims, inferred units, incompatible tasks, related-checkpoint alias transfer, truncated source ingestion and separate-panel coverage inflation. Preserve earlier failed receipts and all existing integrity checks. Repair source adapters, data contracts and validation where required, then rerun data and registry validation with scoring verification.
