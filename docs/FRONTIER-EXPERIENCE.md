# Frontier experience implementation

The production entry in `src/main.tsx` mounts `src/observatory.tsx`, and `src/style.css` supplies the responsive page system. The existing `assets/surface.js` behavior is preserved and served from `public/assets/surface.js`. It renders first; the chart and catalogue experience loads as a deferred React chunk with a visible loading state and a failure message that leaves the hero available.

## Page composition

The page follows five distinct chapters: a mineral frontier, a graphite matched-comparison stage, a total-parameter size ruler, a broad searchable directory and an editorial methods/coverage chapter. Space, typography, thin rules and the mineral/graphite/cobalt/lime palette carry the hierarchy. The frontier uses one large comparison stage and a compact filter rail. The paired stage reports missing location and common-test evidence. The size ruler groups by total parameters and displays activated parameters separately. The directory keeps all catalogue identities in a searchable, paginated table; it is not drawn as hundreds of chart marks. The methods chapter exposes domain coverage and source detail.

The chart module uses pinned visx scales, axes and resize observation with Motion SVG bars. Ranking and exact-table views share the same real observation rows; a compatible domain matrix reports observation counts and opens the original result links. Query parameters preserve cohort, domain, suite, lab, view and selected row. Keyboard and touch select the same marks, and reduced motion keeps values and controls while removing animated transitions. The only selectable views are ranking and exact rows.

## Captured evidence and limits

`scripts/build-observatory-data.mjs` projects the captured 6 MB ingestion input into compact public files before build. It validates model, configuration, suite, source and result references; `public/data-manifest.json` binds projection and deferred-detail SHA-256 hashes to the exact ingestion digest. The browser checks those byte counts and hashes before using the data. `public/data.json` includes the full admitted catalogue and observations, not the legacy preview. `public/data-details.json` holds inspectable source rights, retrieval metadata, identifiers, conflicts and hashes, and is fetched only when a detail disclosure is opened. Neither file contains local snapshot paths, source payloads or endpoint prices.

The captured input contains 508 models, 118 observations, 69 registered suites across 15 domains, and 1,061 source detail records. Nine model identities match captured official release/model pages across eight labs, including Meta. Those identity matches are not benchmark results. The capture marks zero benchmark observations verified, so the default watchlist has nine honest missing-result rows and no score marks. Switching to captured claims shows their raw values, source URLs, units, test context and unverified status. No overall score, zero fill or false confidence interval is presented.

The capture includes 1,328 endpoint price rows, but every rate source excludes redistribution while terms remain unsettled. Values and endpoint payloads are withheld; task-cost scatter and Pareto are explicitly unavailable, and the control cannot be selected. The source record contains no lab headquarters, so a US–China winner is not assigned. These are current source limitations, not implementation assumptions.

## Bundle and verification

`npm run test:frontier` builds the production app and measures gzip over the JavaScript files referenced by the initial HTML script and module-preload tags. The 30 September 2026 captured build measured **69,672 bytes / 68.04 KiB** with Node's `gzipSync`, below the 180 KiB initial-JavaScript budget in `docs/DESIGN.md`. The initial entry is 224.30 kB raw; the deferred chart experience is 212.40 kB raw / 66.74 KiB gzip. The catalogue, source detail and endpoint payloads are not embedded in the initial JavaScript entry. The test fails if the measured initial assets exceed the budget or if the chart experience is preloaded.

The test reads the actual public projection and verifies exact digest binding, broad-catalogue counts, missing and unverified states, withheld price fields, and source identifiers. Its built-browser pass delays the manifest to confirm the hero appears first, then exercises cohort/domain/suite/lab filters, view transitions, exact table parity, original result navigation, lazy source detail, touch and keyboard selection, URL persistence, cost-view exclusion, reduced motion and page bounds at 360, 390, 768, 1280 and 1440 px. It writes the measured report plus full-page desktop/mobile and readable chapter screenshots to ignored `test-results/` files.

`npm run verify` retains `verify:foundation` before `test:frontier`. The foundation gate runs strict typechecking, a clean build, unit tests and an independent built-browser regression for the preserved hero and chart interactions. `npm run verify:design` checks the blueprint contract. Earlier failed verification receipts remain in the daemon record; only a current successful run is a pass.
