# Frontier experience implementation

The production entry in `src/main.tsx` mounts `src/observatory.tsx`, and `src/style.css` supplies the responsive page system. The existing `assets/surface.js` behavior is preserved and served from `public/assets/surface.js`. It renders first; the chart and catalogue experience loads as a deferred React chunk with a visible loading state and a failure message that leaves the hero available.

## Page composition

The page follows five distinct chapters: a mineral frontier, a graphite matched-comparison stage, a total-parameter size ruler, a broad searchable directory and an editorial methods/coverage chapter. Space, typography, thin rules and the mineral/graphite/cobalt/lime palette carry the hierarchy. The frontier uses one large comparison stage and a compact filter rail. The paired stage reports missing location and common-test evidence. The size ruler groups by total parameters and displays activated parameters separately. The directory keeps all catalogue identities in a searchable, paginated table; it is not drawn as hundreds of chart marks. The methods chapter exposes domain coverage and source detail.

The chart module uses pinned visx scales, axes and resize observation with Motion SVG bars. Ranking and exact-table views share the same real observation rows; a compatible domain matrix reports observation counts and opens the original result links. Query parameters preserve cohort, domain, suite, lab, view and selected row. Keyboard and touch select the same marks, and reduced motion keeps values and controls while removing animated transitions. The cost control reaches the separate matched-panel task scenario described below.

## Captured evidence and limits

`scripts/build-observatory-data.mjs` projects the captured ingestion input and permitted authority/price facts into compact public files before build. It validates model, configuration, suite, source and result references; `public/data-manifest.json` binds projection and deferred-detail SHA-256 hashes to the exact ingestion, authority and price input digests. The browser checks those byte counts and hashes before using the data. `public/data.json` includes the full admitted catalogue and observations, not the legacy preview. `public/data-details.json` holds inspectable source rights, retrieval metadata, identifiers, conflicts and hashes, and is fetched only when a detail disclosure is opened. Neither file contains local snapshot paths or raw provider payloads. The data projection includes a separate licensed endpoint tariff block.

The captured input contains 508 models, 118 observations, 69 registered suites across 15 domains, and 1,061 source detail records. Nine model identities match captured official release/model pages across eight labs, including Meta. Those identity matches are not benchmark results. The capture marks zero benchmark observations verified, so the default watchlist has nine honest missing-result rows and no score marks. Switching to captured claims shows their raw values, source URLs, units, test context and unverified status. No overall score, zero fill or false confidence interval is presented.

The original capture includes 1,328 routed endpoint price rows whose reuse terms remain unsettled. Those values and endpoint payloads stay withheld. A separate licensed Google pricing capture now supports exact text-token task estimates and matched-panel cost/Pareto; other providers remain unknown. Later independently evaluated authority observations and source-backed lab classification support the matched US–China chapter. These later facts do not change the original community audit's zero-admitted status.
