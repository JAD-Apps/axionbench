Keep the
evidence open.

MetaBench combines published results into task-specific capability estimates. It is a synthesis of source snapshots, rather than a new evaluation run.

Inspect the source data ↗
01 How scores are combined

Each source score is divided by that benchmark’s best score, then combined using capability-specific weights. The display multiplies that fraction by 100. An index of 100 means the source leader’s level; it is not a task success percentage. Missing sources are excluded from the point estimate and the remaining weights are renormalized.

02 What the ranges mean

Whiskers show a sensitivity range for missing results, using the model’s lowest and highest observed normalized source scores. They are not statistical confidence intervals. Weighted coverage tells you how much of a capability’s source weight has reported results. A narrow range can still have low coverage.

Profiles show point estimates for models with data on all six routed capabilities. Heatmap gaps remain empty. See rankings and the model inspector for coverage and ranges.

03 How task pricing and routing work

Estimated task cost = blended API dollars per million tokens × task tokens ÷ 1,000,000. Prices are imported from the supplied snapshot, originally from JadBot’s pricing table and the LiteLLM pricing catalogue ↗. The fixed blend is 30% input, 60% cache reads, and 10% output. Actual token use, cache hits, and retries will change task cost.

Economy maximizes capability per estimated dollar among models at or above 60% of the best point estimate. Balanced uses an 85% threshold. Frontier picks the highest point estimate, with lower cost breaking ties. All picks use the full snapshot, independently of the explorer’s developer filter.

04 Limits and source provenance

The 3D axis is a proxy built from front-end, one-shot, and reasoning signals; it is not a dedicated graphics evaluation. Security is informational and excluded from routing because many models share a rating of 200 in BridgeBench’s security results ↗, which the supplied snapshot treats as a possible floor.

Vendor-reported rows and the GPT-6 Sol proxy used for GPT-6.1 Sol’s terminal result are marked in the model inspector. Claude Haiku 4.5 has no results in this snapshot. Source sites may have changed since the dates below; this page does not automatically refresh scores or prices.
